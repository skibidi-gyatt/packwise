# Website transport entry

The website at `/` opens on a transport-selection landing page. Truck, container, saved transport and sample truck selections open a setup form. Submitting valid interior dimensions, door dimensions and a manually entered payload opens the existing Planner. The Planner's rendered interface is unchanged; its initial transport and initial plans use the selection. Reloading the website returns to transport selection. Saved transports reuse the existing device-local transport library.

Photo capture accepts a photo and an optional second angle, with separate camera and gallery choices. Images are resized locally and sent only when Estimate is clicked. They are not included in saved transport records. Demo estimates are enabled by default: occupied, partially obstructed and exterior views can supply approximate interior and opening dimensions based on visible structure and inferred proportions. A marker is optional. The result explains its assumptions and remains labelled as approximate demo dimensions in the planner and saved transport metadata. Unrecognizable images still cannot supply dimensions. Switching off demo estimates restores reference-based checks: unscaled images, retakes and requests for another angle cannot populate dimensions. Unknown axes remain blank. Both modes require review before proceeding. Payload and floor ratings are excluded from the AI output contract and always remain user supplied.

The `transport-capture` action uses the existing server-only runtime AI configuration. It requires `OPENAI_API_KEY` and an image-capable structured-output model configured through `ASTRA_MODEL`. Without that connection, the website explains that estimation is unavailable and retains manual measurement entry. No key is embedded in browser code. Live photo accuracy has not been validated; the contract is tested with mock model responses. Photo estimates are approximate, not certified measurements.

Validation: 40 automated tests pass, TypeScript and the production website build pass. Browser checks covered desktop and 393 px phone layouts, manual entry and selected-transport handoff. An entered 2,000 kg payload correctly triggered the existing manifest-overweight notice. Main planner JSX and styles were preserved. The previously created iPhone project remains available but is not the website entry point.
